# Project Setup

This project has two halves: a Solidity/Hardhat backend (the smart contracts)
and a React/Vite frontend (the dApp UI). You'll run both locally against a
private test blockchain (Ganache) while developing.

If you're brand new to any of this — Solidity, Hardhat, MetaMask — that's
fine, follow the steps in order and you'll have a working local setup by the
end.

## 1. Install the tools

- **Node.js** (v20+) — https://nodejs.org
- **Ganache** (the desktop app, not just the CLI) — https://archive.trufflesuite.com/ganache/
  This is your own private local blockchain. Nothing on it is real money.
- **MetaMask** browser extension — https://metamask.io
  This is the wallet you'll use to sign transactions in the browser.

## 2. Install project dependencies

From the repo root:

```bash
npm install
```

Then also install the frontend's own dependencies:

```bash
cd frontend
npm install
cd ..
```

## 3. Start Ganache

Open the Ganache app and start (or create) a workspace. Note two things
from its main screen:

- **RPC Server URL** — usually `http://127.0.0.1:7545`
- **Network ID / Chain ID** — usually `1337`

If yours differs, you'll need to update `hardhat.config.ts` (the `ganache`
network's `url`) to match.

Each account Ganache shows comes pre-funded with fake ETH. Click the key
icon next to any account to reveal its private key — you'll need one in the
next step.

## 4. Set up your Hardhat keystore

Hardhat keeps secrets (like private keys) out of the repo in an encrypted
local keystore, not in a `.env` file. Set it up once:

```bash
npx hardhat keystore set GANACHE_PRIVATE_KEY
```

You'll be asked to:
1. Create a keystore password (first time only — remember this, it unlocks
   all your local secrets).
2. Paste in the private key you copied from Ganache in step 3.

This is stored on your machine only — never commit it, and everyone on the
team sets their own using their own Ganache account.

## 5. Compile the contracts

```bash
npx hardhat build
```

This compiles everything in `contracts/` and generates typed artifacts.
Run this again any time you edit a `.sol` file.

## 6. Deploy to your local Ganache

```bash
npx hardhat ignition deploy ignition/modules/Counter.ts --network ganache
```

Enter your keystore password when prompted, then confirm the deploy. This
writes the deployed contract address to
`ignition/deployments/chain-<id>/deployed_addresses.json` — this file is
gitignored for local networks, since everyone's local Ganache has different
addresses. (See [Adding a new contract](#adding-a-new-contract) below for
deploying additional contracts.)

## 7. Run the frontend

```bash
cd frontend
npm run dev
```

Open the URL it prints (usually `http://localhost:5173`).

## 8. Connect MetaMask to Ganache

In MetaMask:
1. Add a network manually — RPC URL and Chain ID from Ganache (step 3).
2. Import an account using one of Ganache's private keys (Account menu →
   Import Account), so you have test ETH to work with in the browser.

Now `http://localhost:5173/counter-demo` should let you read/write to the
deployed contract, with MetaMask popping up to confirm transactions.

## Everyday workflow

```
edit contracts/*.sol
  → npx hardhat build
  → npx hardhat test              (if there are tests)
  → npx hardhat ignition deploy ignition/modules/<Module>.ts --network ganache
  → use it from the frontend
```

## Adding a new contract

1. Add `contracts/YourContract.sol`.
2. Add `ignition/modules/YourContract.ts`:
   ```ts
   import { buildModule } from "@nomicfoundation/hardhat-ignition/modules";

   export default buildModule("YourContractModule", (m) => {
     const yourContract = m.contract("YourContract");
     return { yourContract };
   });
   ```
3. `npx hardhat build && npx hardhat ignition deploy ignition/modules/YourContract.ts --network ganache`
4. In React, use it immediately — no new wiring file needed:
   ```js
   import { getContract } from '../contracts';
   const contract = getContract('YourContract', 1337, signer);
   ```
   `frontend/src/contracts/index.js` auto-discovers any compiled artifact and
   deployed address by contract name.

## What's gitignored (and why)

- `artifacts/`, `cache/` — regenerated by `npx hardhat build`, never hand-edited.
- `ignition/deployments/chain-1337/` — your personal local Ganache deployment.
  Everyone has their own; committing this would just cause noisy conflicts.
- A deployment to a **real shared network** (e.g. `sepolia`) is different —
  that address should be the same for the whole team, so that one *does* get
  committed. Ask before deploying to a shared network.

## Troubleshooting

**`Reverted without reason` on deploy** — usually an EVM version mismatch
between the Solidity compiler and Ganache's hardfork setting. This project's
`hardhat.config.ts` already pins `evmVersion: "london"` to match Ganache's
default; if you change Ganache's hardfork setting, this may need revisiting.

**`Secrets are not yet supported in the console task`** — `npx hardhat
console` can't resolve keystore secrets yet. Use a script instead:
`npx hardhat run scripts/<script>.ts --network ganache`.

**Reconciliation / "Artifact bytecodes have been changed" on deploy** — a
previous deploy attempt left a stale record. Rerun with `--reset`:
`npx hardhat ignition deploy ignition/modules/<Module>.ts --network ganache --reset`.
